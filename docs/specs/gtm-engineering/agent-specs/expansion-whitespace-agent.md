# Expansion (Whitespace) Agent (template)

Part of the [agent spec templates](README.md). Fill the bracketed fields for [COMPANY_NAME].

## Purpose

Find whitespace in the existing customer base (products, seats, regions or business units a customer does not yet use) and propose expansion opportunities with evidence and a size range.

## Trigger and cadence

Scheduled, once per eligible customer per cycle (`[ASSUME]` cycle length), plus on request from the account owner.

## Eligibility rules

A customer is in scope unless excluded. Starting values below are examples to replace with your own.

| Rule | Example value | Why |
|---|---|---|
| Minimum customer age | 6 months `[ASSUME]` | Too early to judge fit or whitespace |
| Renewal cooldown | No renewal in the last 60 days `[ASSUME]` | Leave the account team free to finish the renewal |
| Open expansion opportunity | Excluded | Avoid duplicates |

Report coverage each cycle as eligible customers over all customers, and list the excluded customers with the rule that excluded them.

## Inputs

| Source | Fields (allow-listed) |
|---|---|
| [CRM] account | Products owned, contract dates, segment, vertical, owner |
| Product catalog | Products and the rule for who they fit |
| Aggregated usage | Trends only, never record-level customer data |
| Similar customers | Product mix of customers in the same segment and vertical |

## Output contract

```json
{
  "account_id": "",
  "whitespace": [{"product": "", "evidence": [], "fit": "high|medium|low"}],
  "proposed_opportunity": {"product": "", "size_low": 0, "size_high": 0, "basis": ""},
  "reason_not_proposed": ""
}
```

The size range is computed from price-book and quantity inputs by code, not generated by the model.

## HITL policy

The account owner accepts, edits or rejects each proposal. Only an accepted proposal creates an opportunity in [CRM]. Report pipeline created and keep it separate from bookings: pipeline is not revenue.

## Evals

- Human-written reference decisions for a set of accounts (propose, do not propose, and why).
- Checks: excluded customers are never proposed, evidence is cited, size range matches the computed range.
- Re-run the test set after every prompt or rule change. See the [Agent Eval Checklist](../../../playbooks/Agent_Eval_Checklist.md).

## Impact metric

Expansion opportunities sourced per quarter and their size range, baselined against the quarters before launch. Measure acceptance rate by account owner.

## Stop rule

Pause the agent if reviewers reject most proposals for a cycle; log the reasons and notify the agent owner.
